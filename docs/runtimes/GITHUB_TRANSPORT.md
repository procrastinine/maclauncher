# GitHub metadata transport

Runtime discovery uses `src/modules/shared/runtime/github-transport.js` for GitHub release, tag, commit and Actions metadata. Requests follow explicit Reload, version, Play or tool actions. Importing modules, reading runtime state and opening a runtime panel perform no authentication or network requests.

The main process shares one transport across backend workers. Its first API request reads an existing `GH_TOKEN` or `GITHUB_TOKEN`, or obtains the installed GitHub CLI's token with `gh auth token --hostname github.com`. This lookup, including an unavailable CLI or authentication result, is cached for the application session. Tokens stay in process memory; workers receive metadata and authentication status. Metadata pages use Node HTTPS rather than repeated CLI processes. Standalone Node callers use the same transport within their process.

When the REST API reports an exhausted quota, public release pages, expanded asset lists, Atom feeds and Git HTTPS reference advertisements supply supported metadata. These requests use official GitHub hosts without authentication headers. Release SHA-256 digests come from published asset metadata; exact download sizes come from HEAD responses for the assets selected by each runtime. Rounded page sizes are never used as byte counts. Git reference advertisements resolve lightweight and annotated tags to exact commits without requiring Git installation. An unavailable digest or commit is not replaced with a guessed identity.

Requests share in-flight work and a bounded memory cache. Metadata is cached for fifteen seconds; asset HEAD responses with the same published SHA-256 can be reused for five minutes. A changed digest gets a separate size lookup. Canceling one caller leaves other subscribers active; canceling every subscriber aborts the underlying request. At most eight network requests run concurrently. Response bodies are limited to 32 MiB, redirects stay on approved GitHub HTTPS hosts, and credentials are removed when the origin changes.

`github-releases.js` provides bounded release, tag and commit queries. Its optional `assetFilter(asset, release)` limits size lookups without discarding published asset names or digests. `github-runtime-catalog.js` keeps engine mapping separate from transport and source identity resolution. `github-actions-catalog.js` uses the same authentication and request service. Actions endpoints without public equivalents can require existing GitHub authentication; public MacLauncher Builds catalogs do not require it. Artifact downloads retain their provider's consent and authentication requirements.
