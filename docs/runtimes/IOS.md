# iOS and iPadOS applications

MacLauncher runs unencrypted ARM64 `.ipa` applications on Apple Silicon through PlayCover’s PlayTools framework and Mac Catalyst.

Library names use `CFBundleDisplayName`, `CFBundleName` or the bundle identifier. Icon inspection reads declared loose PNG variants directly from the package and selects the largest valid declared image; conventional application icon filenames provide a fallback. Apple's optimized CgBI icon PNGs, which store non-interlaced 8-bit BGR or BGRA scanlines up to 2048 pixels, are converted to standard PNGs. An application whose icon exists only in a compiled asset catalog (`Assets.car`) shows the generic iOS icon. Inspection does not unpack or modify the application.

**Play** prepares the imported IPA and starts its application. A missing PlayCover runtime is downloaded after confirmation, then the game starts automatically. Installing or opening the standalone PlayCover app is not required. In Runtimes → PlayCover, the refresh control lists [PlayCover releases](https://github.com/PlayCover/PlayCover/releases), including prereleases labeled **Pre-release**. Installed versions can be selected, set as the default or removed there. Play uses the game's explicit version, then the saved default. Without either, it reuses the newest installed version, otherwise it installs the newest listed release after confirmation. Downloads occur only after an install action or consent during Play.

MacLauncher stores runtime versions in its Application Support directory and handles each game's setup automatically. Preparation extracts a private application copy, adjusts its Mach-O platform and library commands, embeds PlayTools and signs the derived app locally. Later launches reuse that copy; changing the IPA or PlayTools version rebuilds it automatically while retaining game data, input settings and keymaps. Original packages remain unchanged. No app is installed in Applications, and SIP, system signing policy and the original app's permissions are not changed.

The app runs with an OS-enforced file sandbox, a private home, temporary files and preferences. Only its prepared bundle, private storage, selected graphics libraries and required system resources are accessible. **Network access** is unchecked by default and uses the shared game setting and application policy. This blocks IPv4 and IPv6 connections, UDP traffic and DNS, including loopback access and child processes. Checking it permits connections, local socket binding and incoming game traffic without relaxing file isolation. Original entitlements, account groups, cloud containers, camera, microphone and location permissions are not imported.

Shared shader effects process supported Metal drawables in place and preserve the application's UIKit layers. The adapter matches the drawable’s UIKit scene to its live Mac window. Opaque Metal game layers also support shared spatial scaling and LSFG through an output layer beneath existing UIKit controls. The window stays at its existing size; supported 1×, 1.5× and 2× resolution settings allocate the game drawable at output size divided by the selected factor. Auto preserves the application’s requested render size. Transparent game layers retain in-place color effects. This presentation path submits the drawable’s color image. PlayTools' input settings and keymaps use private storage for each application. Its normal PlayCover container is not accessible, and existing external keymaps are not imported.

Settings → iOS and the per-game Runtime Settings window expose keyboard and mouse mapping, mouse sensitivity, scroll-wheel gestures, pausing keymapping during text input, window mode, dimensions and device model. The default Resizable mode uses PlayTools' window handling to keep the app's display bounds aligned with the Mac window. Fixed dimensions remain available for apps that need them. Keymapping pauses during text input by default. Global defaults and per-game overrides use the same fields. Changes take effect on the next launch and are written to the app’s private PlayTools settings; existing keymaps are preserved. **Cmd-K** toggles PlayTools’ keymap editor while keyboard and mouse mapping is enabled. Keymaps are saved automatically for that game. Discord activity and PlayChain remain disabled.

**Extract IPA contents** exports the package's resources and compiled binaries to a reusable private folder. **Show extracted contents** opens that folder in Finder. Exports contain the original resources and compiled binaries.

## Module architecture

The module is `src/modules/ios`. Detection and preparation run off the Electron main thread. ZIP paths, sizes, duplicate names, special files and entry checksums are checked before publication. Mach-O rewriting requires real header padding and refuses encrypted load commands. Preparation is cached against source and derived-file identities; extraction replaces one derived tree transactionally.

The included ARM64 compatibility adapter redirects PlayTools' explicit container file URLs to the app's private home. When UIKit provides no vendor identifier, it supplies a persistent UUID stored separately for each game. This avoids startup crashes in applications that assume the identifier is always available. Existing system identifiers, other URLs and filesystem permissions are unchanged. The selected iPad or iPhone model is reported separately by PlayTools. Its owned Swift/C/Objective-C sources are under `src/modules/ios/native`; `node scripts/stage-ios-helper.mjs` builds the small supplemental library for macOS 12 or later. Normal installation uses that included library and does not need developer tools.

The catalog follows PlayCover releases and records their source revisions and disk-image identities. Listed releases require Apple Silicon and macOS 12 or later. The refresh control queries PlayCover's release catalog only on request. MacLauncher downloads the selected release directly and extracts its bundled PlayTools framework and library dependencies. No PlayCover application is retained by a new installation, and no developer tools or source build are needed. Releases without a disk image are shown as unavailable.

The manager verifies the archive and records the PlayTools binary and dependency hashes. Existing managed installations and saved selections remain usable. No PlayCover GUI process is used to install or launch games. The native launch uses the common process, network and graphics services.
