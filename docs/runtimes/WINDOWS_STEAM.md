# Windows Steam games

CrossOver and Sikarugir use the same optional Steam client bridge. It connects a Windows game's original Steam API to the running Steam client for Mac. Steam supplies account, ownership and ticket responses.

Play prepares the bridge when the game includes `steam_api.dll` or `steam_api64.dll` and its app ID is recorded in a local Steam library manifest or a completed MacLauncher Steam download. Missing bridge files and genuine Windows client components join the consented Play installation. The bridge has no separate Runtimes control. Declining or failing its optional preparation continues the ordinary launch; another explicit Refresh permits a new offer.

Client discovery and installed-component status are offline. A consented component installation reads Valve's current download metadata and verifies the selected archive against its publisher-supplied content address. The launcher keeps verified files for offline use. It does not require a particular running Steam client version or compare that client's files with a hash list. Starting Steam uses the existing separate Internet consent and per-game startup preference.

The game runs in the selected CrossOver bottle or Sikarugir environment. The bridge and genuine Windows client files remain in MacLauncher's managed runtime directories outside that environment. Wine loads them through managed paths, `WINEDLLPATH` and launch-specific DLL overrides. An owned helper writes only the Steam discovery entries under `HKCU\Software\Valve\Steam`, including its own active process ID, the managed client DLL paths, `SteamPath` and `SteamExe`, and stays alive as the game's parent. The bridge creates no environment copy and installs no files into `drive_c`. Ordinary Wine settings and game drive mappings use the selected environment. An owned loader maps the genuine Windows Steam client DLL without running its Windows initialization, and redirects its shared exports to `lsteamclient`, which loads the native Mac client library. Unsupported executable exports stop the owned process. The loader does not alter the game, its Steam API or its DRM, and it does not modify the installed Wine runtime or the Mac Steam client. The initial executable's TLS callbacks can run before the child loader is installed.

The package supplies Windows i386 and x86_64 components and native x86_64 and arm64 components. Native path conversion uses the selected Wine runtime's exported functions, including the Wine 10 interface. A missing package, client or native architecture disables bridge preparation. Native API failures remain subject to the game's client-error handling. Existing copies under `steam-environments` are preserved and no longer selected by the bridge. They may contain saves and are not removed automatically.

Steam and the game's own checks determine whether a title can start. A successful client connection does not establish compatibility with a game's other Windows APIs, graphics or anti-cheat requirements.
