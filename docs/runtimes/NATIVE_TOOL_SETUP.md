# Native runtime and tool setup

Normal game launch uses an included or installed runtime directly. Immutable included bundles need no installation copy. Build tools are needed only for an explicit source build in Runtimes or through a developer API, and decompilers only for an explicit game export. The launcher does not install system development tools or dependencies in the background. Managed players and tools that support local builds offer imports in Runtimes; registration records their local identity and distinguishes it from verified source builds. Fixed included components require no manual setup.

`userData` normally means `~/Library/Application Support/maclauncher/`. Managed runtimes go in `userData/runtimes/<managerId>/<version>/`; game-specific staging, saves and reports go in `userData/games/<gameId>/`. Manually registered executables remain at their selected persistent locations, such as `~/Applications/MacLauncher Runtimes/`.

Native builders search `/opt/homebrew/bin`, `/usr/local/bin`, then PATH. Alternative distributions are resolved through those directories or the launcher’s PATH. Build actions stage clean tracked source and turn CMake dependency downloads off. The shared initializer acquires the required source revisions.

## Managed runtimes and decompilers

- **AliceSoft source tools:** **Decompile** in the inspector runs the matching pinned Sys3dc or Xsys35dc directly from included resources. Versions are grouped under **AliceSoft** in Runtimes. Explicit external/development registrations retain their user-data records; UTF-8 exports stay in that game's private data. [source export](VN_ENGINES.md#alicesoft-source-export) describes exact pins, supported formats and bounds.
- **UndertaleModTool:** **Decompile** confirms a missing [UndertaleModTool CLI](https://github.com/UnderminersTeam/UndertaleModTool) download, installs the selected version and continues automatically. The native CLI is managed under the launcher's `userData/runtimes/` tool directory; the pinned release includes its own .NET runtime, so a separate .NET SDK is unnecessary. Advanced version/import controls remain available in Runtimes. [GameMaker tools](GAMEMAKER.md) describes versions, variants and hashes.
- **Official GameMaker:** register an already installed `runtime-<version>` directory, or use the explicit official install action. Studio 2 setup installs the vendor's native Igor tool automatically; pinned Studio 1.4.9999 setup decodes only its public Mac module without Igor or a compiler. Launches use the extracted native runner directly. [GameMaker setup](GAMEMAKER.md) describes the pinned bootstrap URL, managed installation paths and required package sizes.
- **Native Steam API:** compatible consumers use the included ARM/Intel [offline API](STEAM_API.md) automatically. No installation is needed. Configuration and local state remain per game; app resources and originals remain read-only.
- **GameMaker software OpenGL:** native helpers are excluded from the app. Existing local versions remain explicit; Automatic otherwise uses ordinary runner graphics. Optional development builds need Apple's Command Line Tools (`xcode-select --install`, installed in `/Library/Developer/CommandLineTools`) and use `/usr/bin/clang` plus `/usr/bin/codesign`. Output lives under `userData/runtimes/gamemaker-opengl-helper/<version>/`. Source/library identities and compiler options remain recorded; see [GameMaker](GAMEMAKER.md).
- **Ikemen GO:** install a supported Mac release in **Runtimes**; no compiler is needed for these binary installs. **HashLink:** Play selects a compatible public download or the included adapted typed-ABI runtime. Missing downloads and Rosetta on Apple Silicon use the normal consent flow. Runtimes provides explicit version selection and Refresh; the included typed-ABI build is separate from stock HashLink releases. [native engine notes](OTHER_ENGINES.md) contains the corresponding reference.
- **HashLink 1.9 Mac graphics v2:** normal Play runs the included `1.9-macos-v2` package directly. Optional source Build uses the same Apple compiler and CMake tools plus system `make` to build the Intel VM and matching native modules. `node scripts/init-submodules.cjs -- src/external/hashlink src/external/krkrsdl2` acquires the HashLink and pinned SDL2 sources. The default SDL checkout is `src/external/krkrsdl2/external/SDL` at `53dea9830964eee8b5c2a7ee0a65d6e268dc78a1` (SDL2 2.0.22); the developer build API can accept an equivalent clean local checkout. The builder reads old HashLink 1.9 Git objects, checks out that exact commit only inside owned runtime data, and compiles bundled image/audio codec sources. No Homebrew Intel graphics libraries or automatic downloads are required. Native output goes under `userData/runtimes/hashlink/1.9-macos-v2/build-output/bin/`; compiler path maps cover private roots, and source/overlay hashes and SDL/OpenAL identities are recorded. Existing installed `1.9` packages retain their exact version and hashes. Source references: [HashLink 1.9 source](https://github.com/HaxeFoundation/hashlink/tree/4a4cfe91f3388a0b05bf2e45e7c4e38bae686dc6) and [pinned SDL source](https://github.com/libsdl-org/SDL/tree/53dea9830964eee8b5c2a7ee0a65d6e268dc78a1).
- **Ren'Py SDK/Python:** use the existing Ren'Py runtime manager and extraction tooling; inspect the extraction report for the selected Python version/source. Manual embedded Python preparation is documented in [Development](../DEVELOPMENT.md#embedded-python-runtime) and installs into `src/resources/python/`. A system alternative is `brew install python@3.12` and an explicit `PYTHON3=/opt/homebrew/bin/python3.12` environment for CLI extraction (`/usr/local/bin/python3.12` on Intel). Metadata-only save inspection needs no Python installation.
- **Rosetta:** Intel-only runtimes on Apple Silicon use Apple's system translator. Play can offer installation after explicit license consent, then resume the game; installed Rosetta is reused. macOS installs it under `/Library/Apple/`, not Launcher Data. The manual fallback is Terminal in Applications → Utilities (`/System/Applications/Utilities/Terminal.app`), followed by `/usr/sbin/softwareupdate --install-rosetta` and Apple's prompts. Related references: [Apple's installation guide](https://support.apple.com/en-us/102527) and the [shared prerequisite service](ROSETTA.md).

Tool-source links and prerequisites should accompany instructions for new actions. Explain whether a tool is needed for installation, building, inspection or every launch; an available runner directory should bypass unnecessary setup work.

## GameMaker software OpenGL

An official runner's accelerated-only pixel-format request can fail when the requested graphics format is unavailable. Apple's [pixel format documentation](https://developer.apple.com/library/archive/documentation/GraphicsImaging/Conceptual/OpenGL-MacProgGuide/opengl_pixelformats/opengl_pixelformats.html) describes format selection and nil results when a request cannot be satisfied.

The helper calls the original initializer first. Only after a nil result does it retry without the acceleration requirement, preserving the other attributes. Version **software-gl-v3-universal** additionally uses logical coordinates for the checksum-bound **1.4.9999** legacy runner after a successful Apple software-renderer selection. Selection is cached before view attachment; rendering does not query context/format state each frame, and original AppKit converters still run. Successful hardware formats, modern profiles and unrelated views retain their conversions. **v1** retains the pixel-format workaround alone; **v2**, **v4** and **v5** are explicit alternatives. Sources, pins and library hashes are listed in [`opengl-helper-versions.json`](../../src/modules/gamemaker/runtime/opengl-helper-versions.json). The helper changes pixel-format selection and coordinate handling; it retains the selected Apple software renderer and original game shaders.

The helper affects the separately staged, ad-hoc-signed runner through `DYLD_INSERT_LIBRARIES`; the installed vendor runner and system libraries remain untouched. Disabling the setting omits the helper environment.

## Native Steam API helper

Normal Play reads the included `maclauncher-offline-abi-0.5.0-universal` library directly. The encrypted-ticket loader is included separately and rejects authentication/decryption requests. No SDK, compiler or helper installation is needed.

Development rebuilds use the standalone [API builder](../../src/modules/shared/runtime/steamworks/native/offline-0.5.0/build.cjs) and [ticket builder](../../src/modules/shared/runtime/steamworks/native/ticket-0.1.0/build.cjs). They require [Node.js](https://nodejs.org/) and Apple Command Line Tools (`xcode-select --install`, installed under `/Library/Developer/CommandLineTools`), with a new absolute output directory. Both compile explicit ARM/Intel macOS 13 targets using only system libraries, preserve neutral compiler source paths and record source/native checksums. Complete MIT source and ABI fixtures accompany each package; changed native behavior requires a new code version and compatibility profiles. Related references: [Steam support](STEAM_API.md) and [upstream maintenance](../UPSTREAMS.md).
