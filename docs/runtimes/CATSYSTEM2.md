# CatSystem2

CatSystem2 imports expose archive and script tools in the inspector. Detection requires both a structurally valid `scene.int` KIF archive and an independently identified original CatSystem2 executable. It checks the selected directory and its `data/` child, preserves case, and reads the original runner's fixed PE version. A loader's product version is not treated as the engine version.

**Export scripts**, in the inspector's Scripts group, decodes `.cst` CatScene programs, `.cstl` localization tables and compressed `.fes` front-end text directly from the original archives. Output includes the decoded member, typed JSON, and a readable UTF-8 transcript. Exports preserve command and unknown line types. Archive inspection reports the formats, encryption, members and original engine version. The advanced archive export defaults to `scene.int`; the backend API can select another identified `.int` archive by filename.

Exports belong to `userData/games/<gameId>/modules/catsystem2/`. Each archive generation retains its numeric index in a separate output directory, including repeated filenames. Exports never overwrite the original game or silently select one generation. Nothing is extracted during import.

Encrypted KIF tools use the Included **MacLauncher KIF cipher helper 1.0.0-ml1**, a shared universal Intel/Apple Silicon executable requiring macOS 11.0. It uses the system CommonCrypto library. No installation or compiler is required. The launcher verifies the exact source, executable, manifest, CPU slices and signature before use. Original `KEY_CODE` / `V_CODE2` resources are read by a bounded PE parser; keys remain in memory and travel to the helper over stdin.

The reader supports the published KIF layout with 64-byte names, the 1999 MT seed recurrence, Beaufort names and little-endian Blowfish blocks. An encrypted member's final incomplete block remains plaintext. CatScene tables and zlib lengths are checked; CSTL currently requires its zero-reserved header and valid UTF-8 language records. Text decoding uses the Included `cp932-2.01-eudc-ml1` mapping, independent of Node's ICU version. FES text defaults to strict CP932; the reader falls back to strict UTF-8 when CP932 rejects the bytes and records the selected encoding. Unknown key resources or archive variants fail with a specific format error. Indexes, decompression and exports have aggregate byte/count limits, and changed source files abort an operation.

The Node [HG-3 reader](../../src/modules/catsystem2/image-hg3.js) supports bounded lossless 24/32-bit frames, cropped RGBA output, canvas offsets and repeated frame IDs. It adapts [TriggersTools.CatSystem2](https://github.com/trigger-segfault/TriggersTools.CatSystem2) algorithms and retains the [MIT notice](../../src/modules/catsystem2/resources/TriggersTools-MIT.txt). Image decoding does not execute KCS/FES programs.

Not yet supported for play. [FelineSystem2](https://github.com/kokseen1/FelineSystem2) remains a read-only development reference. Its unlicensed core and embedded game assets are not distributed.

The owned readers follow the primary [KIF](https://github.com/trigger-segfault/TriggersTools.CatSystem2/wiki/KIF-Archive), [key-resource](https://github.com/trigger-segfault/TriggersTools.CatSystem2/wiki/V_CODEs), [MT1999](https://github.com/trigger-segfault/TriggersTools.CatSystem2/wiki/Mersenne-Twister), [CatScene](https://github.com/trigger-segfault/TriggersTools.CatSystem2/wiki/CST-Scene), [CSTL](https://github.com/trigger-segfault/TriggersTools.CatSystem2/wiki/CSTL-Scene-Languages) and [FES](https://github.com/trigger-segfault/TriggersTools.CatSystem2/wiki/FES-Screen) format documentation from [TriggersTools.CatSystem2](https://github.com/trigger-segfault/TriggersTools.CatSystem2).

The developer-only [helper recipe](../../src/modules/catsystem2/runtime/stage-crypto.cjs) pins Apple clang 21.0.0 and macOS SDK 27.0. Xcode Command Line Tools install under `/Library/Developer/CommandLineTools` through `xcode-select --install`; they are build prerequisites only. Stage into an empty resource directory and verify its declaration and complete inventory before publishing a new helper version. See [runtime distribution](RUNTIME_DISTRIBUTION.md).
