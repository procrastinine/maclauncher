MacLauncher 0.6.0 follows 0.3.1, and these notes cover every change since then. It adds Android, iOS, PlayStation 5, Nintendo Switch and Switch 2, DOS, Half-Life, 32-bit Mac and video playback, together with a graphics and effects layer shared by every runtime. Windows games gain Sikarugir (Wine) beside CrossOver, a per-game choice of graphics translators, the KosmicKrisp Vulkan driver, DLSS through MacLauncher's temporal upscalers and a Steam client bridge. A new External window downloads games from Steam, Epic Games, GOG and itch.io, and Android apps from Google Play, F-Droid and IzzyOnDroid. Runtimes download as versioned packages after consent, and games play from their original folders. MacLauncher itself comes as separate apps for Apple Silicon and Intel, and both update themselves.

The app includes graphics 0.3.8.

- [Android](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/game-types/ANDROID.md) APK packages play on Apple Silicon. The default runtime, MacLauncher Android, runs the complete AOSP Android 16 framework on either of two execution engines, JVM and ART, which come in one package with a single version selection in **Runtimes**. Mac.apk and AIM are optional alternatives, and each runtime keeps its own settings and app data.
- Unencrypted ARM64 [iPhone and iPad apps](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/game-types/IOS.md) packaged as `.ipa` files run on Apple Silicon through the PlayTools framework from PlayCover.
- Unpacked, decrypted [PlayStation 5](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/game-types/PS5.md) games run through AnyPS5, which converts their programs into macOS executables, or through the optional Prosper, which runs the original programs directly. Both runtimes need macOS 26 or later.
- On Apple Silicon, [Nintendo Switch](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/game-types/SWITCH.md) games run through nxnative from NSP, NSZ, XCI and XCZ containers, NUP containers and decrypted Switch and Switch 2 dumps. NUP containers and decrypted dumps play without `prod.keys`, and a game is shown as **Nintendo Switch 2** once preparation identifies a Switch 2 title.
- [DOS](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/game-types/DOS.md) programs run in DOSBox Staging. [Half-Life](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/game-types/HALF_LIFE.md) and mods built on its game code run on Xash3D FWGS, a native engine that reads the original game data.
- Current macOS cannot launch apps built only for 32-bit Intel (i386). Such apps now run through mac32 as the [32-bit Mac](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/game-types/MACOS.md#32-bit-mac) runtime.
- Local [video files](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/game-types/VIDEO.md), as well as folders of videos imported as playlists, play in mpv with the same effect chains that games use. **Tools → Video processing** previews a video with its effects and exports it as a separate MP4 file.
- [Sikarugir (Wine)](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/runtimes/SIKARUGIR.md), a free Wine distribution that MacLauncher downloads from its publisher, is the default runtime for [Windows games](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/game-types/WINDOWS.md), and an installed CrossOver remains available. Play prepares a private Wine prefix or CrossOver bottle for each game from its original files, or Runtime Settings can select an existing CrossOver bottle or Sikarugir wrapper, which MacLauncher never deletes, recreates or moves. Both runtimes are also offered to other game types whose files include a compatible Windows executable, although known engines keep their usual default. XNA games that FNA cannot run start in them. Automatic titles for Windows games come from Steam download records, a matching Steam app manifest or the install folder.
- [Graphics translators](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/runtimes/TRANSLATORS.md) are chosen per game in CrossOver and Sikarugir: a default Direct3D engine, a translator for each Direct3D version from 8 to 12, a Vulkan driver and video codecs. Settings holds the defaults for all games. Besides the copies that come with the selected Wine, the choices include upstream releases, locally registered files and the user's own copy of Apple's Game Porting Toolkit for D3DMetal. Versions installed in **Runtimes** are stored apart from CrossOver and the Sikarugir Templates, which are never modified. MacLauncher DXVK, an adapted DXVK 3.1.1 from MacLauncher Builds, is one of the DXVK choices.
- [KosmicKrisp](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/runtimes/KOSMICKRISP.md), the conformant Vulkan 1.4 driver for Apple Silicon from the Mesa project, is available next to MoltenVK for Vulkan games, the Vulkan-based Direct3D translators in Wine and ANGLE's Vulkan renderer for Android. MacLauncher KosmicKrisp adds the Vulkan features that DXVK, vkd3d-proton and ANGLE use. KosmicKrisp needs Metal 4 on Apple Silicon hardware, and MoltenVK serves Intel Macs, macOS versions before 26 and virtual machines.
- With the Vulkan driver on **Automatic**, a Windows game keeps its Wine runtime's own Vulkan driver. A game that uses MacLauncher DXVK or vkd3d-proton from **Runtimes** runs on MacLauncher KosmicKrisp.
- In games that use [DLSS](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/graphics/INPUTS_AND_ADAPTERS.md#dlss-through-vulkan-translators), MacLauncher's shared temporal upscalers run the Super Resolution evaluations without any setting. This works through DXMT and D3DMetal, and through DXVK and vkd3d-proton on MacLauncher KosmicKrisp or a MoltenVK build with temporal-carrier support.
- [Translator environment variables](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/runtimes/TRANSLATOR_ENVIRONMENT.md) have global values in **Settings → Environment variables** and per-game values, for Wine and its translators, the Android execution engines with ANGLE and the Vulkan driver, and the PlayStation 5 runtimes.
- The [Steam client bridge](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/runtimes/WINDOWS_STEAM.md) connects a Windows game's own Steam API to the Steam client for Mac in CrossOver and Sikarugir, so Steam itself answers account, ownership and ticket requests. Play offers it for a game that includes `steam_api.dll` or `steam_api64.dll` and whose app ID is recorded in a local Steam library or a completed MacLauncher Steam download.
- A shared [graphics and effects](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/graphics/README.md) layer runs on Metal for every runtime, including Wine, Android, iOS, browser games and video. Its chain combines ReShade, RetroArch and mpv shaders, spatial, temporal and neural upscaling, neural restoration and frame generation in any order, and edits apply while the game runs. **Simple** chooses a shader, a scaling method and frame generation, whereas **Advanced…** orders individual rows, each with its own settings and bypass control. Chains can be saved as presets, and **Settings → Graphics** holds the shader library and the presets.
- [Frame generation](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/graphics/README.md#frame-generation) includes LSFG, which uses the models of a purchased Lossless Scaling copy, and three methods that need no model files: VideoToolbox interpolation, MetalFX image interpolation and Vision optical flow. The Output section also has a performance overlay and a frame-rate cap. Keyboard shortcuts assigned in **Settings → Launcher** bypass a running game's effects or save a processed screenshot, which is a 16-bit BT.2020 PQ PNG when the output is HDR.
- [Window graphics](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/game-types/WINDOW.md) apply effects to another app's window or to a display. Each window or display chosen from **File → Apply Graphics…** gets its own library entry and graphics chain. The processed image stacks with the window, passes clicks through and can fill the screen or enlarge the window. Window graphics need macOS 15.2 or later.
- The [External](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/library/EXTERNAL.md) window lists the Steam, Epic Games, GOG and itch.io games installed on the Mac, including those in CrossOver bottles, and imports a selection in the background. Its store tabs browse account libraries and download games with a choice of version, platform and language. For Steam, it can use the account of the running Mac Steam app as well as several separate sign-ins. Its Android tab searches Google Play, F-Droid and IzzyOnDroid, as described in [Android app downloads](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/library/GOOGLE_PLAY.md).
- Play runs games from their [original folders](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/library/GAME_PREPARATION.md#original-game-paths) when the runtime supports their layout, and for input that an engine cannot use in place, it prepares only the adaptation that the engine needs. Engines keep their usual save and configuration locations. On the first startup after upgrading, the library window shows progress while files from [earlier private game folders](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/library/GAME_PREPARATION.md#earlier-private-game-folders) are recovered once into the original folders, with differing files kept beside the originals.
- Games on a disconnected drive or in a moved folder show as [Unavailable](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/library/GAME_PREPARATION.md#unavailable-game-files), and everything MacLauncher stored for them is kept. **Locate…** in the inspector points the entry to the files' new location, and saved `.command` shortcuts follow it unless they were edited.
- When an imported folder has no recognized game at its top level, or several possible games, the import [searches inside it](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/library/DETECTION.md#games-inside-a-folder) and offers the games it finds.
- The inspector gains **Launch arguments**, which are kept with the game and its saved `.command` launcher, and a **Network access** checkbox. Turning it off [blocks the game's Internet and local-network access](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/runtimes/NETWORK_ISOLATION.md) in every runtime.
- [Inspect binary](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/tools/NATIVE_INSPECTION.md) exports static Rizin and Ghidra reports for native programs without running them, including macOS and Windows executables, 32-bit Mac apps and unencrypted iOS packages. The **Decompile** actions of DOS, PlayStation 5 and Switch games use the same tools.
- Runtimes and versioned tools are downloaded when a game first needs them: those that need changes for macOS from [MacLauncher Builds](https://github.com/procrastinine/maclauncher-builds), and the others from their publishers. Play and inspector actions use a compatible installed version first; otherwise MacLauncher asks before the download and then continues. Installed versions work offline, and the app itself includes the core graphics component and internal helpers. MKXP-Z builds from MacLauncher Builds include a [fix for Unicode file names](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/game-types/RPGMAKER_XP_VX.md#macos-file-name-normalization).
- Every runtime manager has its own tab in [Runtimes](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/runtimes/README.md#the-runtimes-window), including small packages that other runtimes load, and each download source has its own version list and refresh control. **Runtimes → Tools → Downloaded files** lists every other downloaded file, largest first, with **Delete** and an offline **Add from file…**. Archives are deleted after extraction. Once per start, an [upkeep pass](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/development/DATA_MODEL.md#derived-data-upkeep) removes files left by earlier launches and downloads. It also removes a runtime version that Play installed only as a default, after a newer default is installed and while nothing uses it.
- Import and Play preparation reuse earlier checks of unchanged runtime files and installer extractions. Work for the selected game runs ahead of background library work.
- MacLauncher runs on macOS 13 or later as two separate apps, one for Apple Silicon and one for Intel, which share the same library, settings and installed runtimes. Individual runtimes keep their own requirements, and [System requirements](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/runtimes/SYSTEM_REQUIREMENTS.md) lists them along with the version of each included package.
- MacLauncher [updates itself](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/UPDATES.md) from its GitHub releases. **Check for Updates…** is in the app menu and in **Settings → Launcher**, and a check at launch can be turned on. The app for the running CPU is installed only after its size and SHA-256 match the release and its build manifest, and after its code signature verifies.
- The [documentation](https://github.com/procrastinine/maclauncher/blob/v0.6.0/docs/README.md) has one page per game type, with separate sections for the library, graphics, runtimes and tools.
