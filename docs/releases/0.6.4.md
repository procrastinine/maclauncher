MacLauncher 0.6.4 adds WineCX as a third Wine runtime and new game types for Doom-engine, Build-engine and LucasArts games. Sikarugir and WineCX games get macOS Game Mode, and the launcher answers clicks before slower work finishes.

The app includes graphics 0.3.11.

- [WineCX](https://github.com/procrastinine/maclauncher/blob/v0.6.4/docs/runtimes/WINECX.md), dappermint's Wine runtime built from CodeWeavers' CrossOver Wine changes on a current Wine release, joins CrossOver and Sikarugir on the same [Wine layer](https://github.com/procrastinine/maclauncher/blob/v0.6.4/docs/runtimes/WINE.md). Settings, translators, private environments, graphics effects and the Steam client bridge work alike in all three. MacLauncher downloads WineCX releases after consent, and each launch checks the files that installation recorded, so **Runtimes → WineCX** offers no **Register custom…**. **Refresh** reads the newest release's macOS requirement from the start of its archive, and a version that needs a newer macOS is listed with **Requires macOS 26 or later** and is not downloaded. WineCX includes no D3DMetal; a D3DMetal version from **Runtimes** can be selected for its games.
- While D3DMetal performs a game's DLSS through game temporal integration in a Wine that reads D3DMetal's adapter variables, such as WineCX's, the game sees an NVIDIA GeForce RTX 4090 and offers its DLSS option. `D3DM_VENDOR_ID`, `D3DM_DEVICE_ID` and `D3DM_DEVICE_DESCRIPTION` set in the [environment variables](https://github.com/procrastinine/maclauncher/blob/v0.6.4/docs/runtimes/TRANSLATOR_ENVIRONMENT.md#d3dmetal) replace these values. MacLauncher reads Wine versions installed by its earlier versions again, without a download, so they gain this and the other capabilities that their Wine supports.
- New game types play Doom-engine games on [UZDoom](https://github.com/procrastinine/maclauncher/blob/v0.6.4/docs/game-types/DOOM_ENGINE.md), Build-engine games on [Raze](https://github.com/procrastinine/maclauncher/blob/v0.6.4/docs/game-types/BUILD_ENGINE.md), and the LucasArts titles that no other game type covers, such as Star Wars: Dark Forces and Outlaws, on [DREAMM](https://github.com/procrastinine/maclauncher/blob/v0.6.4/docs/game-types/DREAMM.md). Each engine is its publisher's macOS app, downloaded after consent. The game data stays in place, each engine's configuration, saves and logs stay with the game in MacLauncher's data, and **Stop** asks the engine to quit. A [DOS game](https://github.com/procrastinine/maclauncher/blob/v0.6.4/docs/game-types/DOS.md#uzdoom-raze-and-dreamm) whose folder holds exactly one main game file of one of these engines offers that engine as a runtime, including DOS games imported earlier.
- Sikarugir and WineCX games start from a private application bundle in the games category, so macOS turns on Game Mode for them in full screen. On macOS 15 and later, macOS asks once per runtime, with a message that names Sikarugir or WineCX, whether its games may use the local network. The answer covers every game and version of that runtime, Play does not wait for it, and the game's **Network access** setting still applies. [Wine runtimes](https://github.com/procrastinine/maclauncher/blob/v0.6.4/docs/runtimes/WINE.md#shared-behavior) describes the bundle.
- The library's first paint shows every unchanged game icon, and local artwork in the Steam and External lists appears with its row. Games found unavailable at the last check, such as games on a disconnected drive, show as unavailable from the first paint.
- **Play** shows the game as starting at once, even while a sleeping drive answers the game's file check, and **Cancel** stops it during that check. Under heavy load, Play no longer stops with **The game's location is not responding.**, because the location's three-second limit starts when the check begins reading it.
- A runtime choice shows at once while the game's save locations refresh afterwards; when they cannot be read, a note under Play names the runtime. The cheat overlay's **Tools** button choice also shows at once and returns to the last applied choice when patching the game fails.
- **Settings**, **Runtimes** and **Credits** open without a loading pause, from one window that is prepared in the background. Views opened in quick succession each get their own window, which appears at once and fills in its controls and data as they load. The gear beside **Runtime** brings a game's open runtime settings window forward instead of opening another. The [UI guide](https://github.com/procrastinine/maclauncher/blob/v0.6.4/docs/development/UI_GUIDE.md#layout-overview) describes the windows.
- At startup, MacLauncher prepares the modules of the most recently played games first, and a game selected meanwhile waits at most for the module being prepared. Installed Wine versions, ScummVM's signature check and the graphics catalog are read without holding up the inspector.
- A saved **Runtimes** default that is not installed gives way to a compatible installed version, such as an installed Sikarugir or WineCX version, so Play asks for no download. **Install** in Runtimes installs the saved default itself, and a version chosen for one game stays exact. [Runtimes](https://github.com/procrastinine/maclauncher/blob/v0.6.4/docs/runtimes/README.md#versions) describes the selection.
- A Vulkan driver selected for a game, such as MacLauncher KosmicKrisp, loads in place of the Wine build's own MoltenVK with every Direct3D engine. Before, a WineCX game, or a CrossOver game on DXMT or D3DMetal, kept the Wine build's MoltenVK.
- Windows .NET and XNA games reach Wine Mono through a short Windows drive path, so a long launcher data path no longer stops Mono from finding its files.
- A translator set that ships its own DXGI for only one game architecture, such as WineCX 4.8.1's DXVK, is offered only to games of that architecture. WineCX's DXMT uses the Wine engine's `winemetal.so`, so Direct3D 11 games start on it. The macOS requirements of DXMT and D3DMetal come from their installed libraries on every Wine source.
- **Runtimes** and the inspector name CrossOver, Sikarugir and WineCX alike, with version labels such as **Sikarugir 1.0.24 · Wine 10.0 rev 8** and **WineCX 4.8.1 · Wine 11.19**, and an installed version's **Includes** line lists its translators in one order.
- A converted [AnyPS5](https://github.com/procrastinine/maclauncher/blob/v0.6.4/docs/game-types/PS5.md#anyps5) game runs from its own prepared macOS application, with the game's library title as its application name and its artwork as its Dock icon. Existing conversions move into this layout without converting again.
- The inspector counts an effect row as running when any of the game's graphics contexts runs it, so a temporal upscaler that runs in the game's renderer no longer reports **Some effects are not running**. Status details name rows as the graphics editor does.
- The Epic, GOG and itch.io tabs of **External** open their sign-in introduction with the store's logo. Progress bars without a known amount sweep with a continuous animation, which slows with Reduce Motion.
- With `--wait`, the command line returns a game's exit status after the game's captured output has closed.
