MacLauncher 0.6.1 includes graphics 0.3.9, which changes how frame generation reaches the screen. It also starts DLSS from a 540-pixel input and corrects adding games by drag and drop.

- [Frame generation](https://github.com/procrastinine/maclauncher/blob/v0.6.1/docs/graphics/FRAME_API.md) shows every generated frame the display can take. With 4× generation from 15 processed frames per second, 60 frames per second reach the screen on 60 Hz, 120 Hz and faster displays. The Metal display link runs at the display's full refresh rate, and a frame that is due waits for a drawable instead of being discarded.
- Delivered frames are presented on a command queue used only for display, so generated frames do not wait behind the game's own GPU work.
- Turning frame generation off, or removing its row, keeps the game image updating. The presenter releases its display link while frame generation is off and creates a new one when frame generation turns back on.
- LSFG frame generation keeps running after a graphics edit, such as a multiplier change or toggling another row.
- New DLSS rows and the DLSS preset start from a 540-pixel input, the size at which DLSS keeps pace for 4× frame generation to reach 60 frames per second on an M2 MacBook. The preset is now named **DLSS · 540p + LSFG 4×**.
- The add overlay opens only for files dragged in from outside MacLauncher.
- KiriKiri games that use KAG3 start with KiriKiri SDL2 MCLv8 from MacLauncher Builds. With MCLv7 they stop because its KAG3 resource manifest has an incompatible format. **Reload versions** and **Install** on the KiriKiri SDL2 page of **Runtimes** add MCLv8, in this and earlier versions of MacLauncher.
- The app includes graphics 0.3.9. [System requirements](https://github.com/procrastinine/maclauncher/blob/v0.6.1/docs/runtimes/SYSTEM_REQUIREMENTS.md) lists each included package with its version.
