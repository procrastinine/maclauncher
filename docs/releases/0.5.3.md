MacLauncher 0.5.3 keeps license texts as ordinary package files, gives Android a single runtime version selection and lists the versions of MacLauncher-built runtimes from the MacLauncher Builds catalogs.

- Runtime packages from MacLauncher Builds, including those the app ships with, keep license texts as ordinary files in `licenses/`, covered by the same [file inventory and checksums](https://github.com/procrastinine/maclauncher/blob/v0.5.3/docs/runtimes/RUNTIME_DISTRIBUTION.md) as other package files. Each distinct text is stored once, and `licenses/components.txt` names the text used by each component.
- The JVM and ART engines come from a single [Android package](https://github.com/procrastinine/maclauncher/blob/v0.5.3/docs/game-types/ANDROID.md), which has one version selection in **Runtimes**, and the earlier separate ART packages are no longer listed.
- Versions of runtimes that MacLauncher builds, including [MKXP-Z with file-name normalization](https://github.com/procrastinine/maclauncher/blob/v0.5.3/docs/game-types/RPGMAKER_XP_VX.md), come from the MacLauncher Builds catalogs.
- The app includes graphics 0.3.6 and the current releases of its included helpers. [System requirements](https://github.com/procrastinine/maclauncher/blob/v0.5.3/docs/runtimes/SYSTEM_REQUIREMENTS.md) lists each included package with its version.

MacLauncher 0.5.3 replaces 0.5.2 and 0.5.1 and also includes their changes:

- [Window graphics](https://github.com/procrastinine/maclauncher/blob/v0.5.3/docs/game-types/WINDOW.md) apply effects to another app's window or to a display. Each window or display chosen in **File → Apply Graphics…** gets its own library entry and graphics chain. The processed image stacks with the window, passes clicks through and can fill the screen or enlarge the window. Window graphics need macOS 15.2 or later.
- [Half-Life](https://github.com/procrastinine/maclauncher/blob/v0.5.3/docs/game-types/HALF_LIFE.md) and mods built on its game code run on Xash3D FWGS, a native engine that reads the original game data.
- VideoToolbox interpolation, MetalFX image interpolation and Vision optical flow [generate frames](https://github.com/procrastinine/maclauncher/blob/v0.5.3/docs/graphics/README.md#frame-generation) without model files. Graphics also gain a performance overlay, a frame-rate cap and shortcuts that bypass effects or save a processed screenshot. The **DLSS · 540p + LSFG 4×** preset becomes **DLSS · 720p + LSFG 4×**, and new DLSS rows start from a 720-pixel input height.
- Play runs games from their [original folders](https://github.com/procrastinine/maclauncher/blob/v0.5.3/docs/library/GAME_PREPARATION.md#original-game-paths) with the engine's own save locations, including Windows games in CrossOver and Sikarugir, Ren'Py, Godot, GameMaker, HashLink, GemRB, FNA and complete Ikemen GO distributions. On the first startup after upgrading, the library window shows progress while files from [earlier private game folders](https://github.com/procrastinine/maclauncher/blob/v0.5.3/docs/library/GAME_PREPARATION.md#earlier-private-game-folders), including the private home folder of 32-bit Mac games, are recovered once into the original folders, with differing files kept beside the originals.
- Import and Play preparation reuse earlier checks of unchanged runtime files and installer extractions. Once per start, an [upkeep pass](https://github.com/procrastinine/maclauncher/blob/v0.5.3/docs/development/DATA_MODEL.md#derived-data-upkeep) removes files left by earlier launches and downloads. It also removes a runtime version that Play installed only as a default, after a newer default is installed and while nothing uses it.
- External → Android reaches Google Play without starting Android. The Android runtime reuses the IDs of ended processes and threads before allocating higher ones.
- MacLauncher runs on macOS 13 or later, with separate downloads for Apple Silicon and Intel. Individual runtimes keep their own macOS requirements.
- MacLauncher [updates itself](https://github.com/procrastinine/maclauncher/blob/v0.5.3/docs/UPDATES.md) from its GitHub releases. **Check for Updates…** is in the app menu and in **Settings → Launcher**, and a check at launch can be turned on. The app for the Mac's CPU is installed only after its size and SHA-256 match the release and its build manifest.
- Games on a disconnected drive or in a moved folder show as [Unavailable](https://github.com/procrastinine/maclauncher/blob/v0.5.3/docs/library/GAME_PREPARATION.md#unavailable-game-files), and everything MacLauncher stored for them is kept. **Locate…** in the inspector points the entry to the files' new location, and saved `.command` shortcuts follow it unless they were edited.
- Work for the selected game runs ahead of background library work.
- The [documentation](https://github.com/procrastinine/maclauncher/blob/v0.5.3/docs/README.md) has one page per game type, with separate sections for the library, graphics, runtimes and tools.
