MacLauncher 0.7.0 adds WineCX as a third Wine runtime, along with new game types for Doom-engine, Build-engine and LucasArts games, and Sikarugir and WineCX games now get macOS Game Mode. In graphics, games that upscale with FidelityFX pass their scene inputs to MacLauncher's temporal upscalers, frame generation shows every generated frame the display can take, and shader options can be imported from existing presets. The inspector names the runtime version Play uses, and the launcher responds to clicks before slower work finishes.

The app includes graphics 0.3.12.

- [WineCX](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/runtimes/WINECX.md), dappermint's Wine runtime built from CodeWeavers' CrossOver Wine changes on a current Wine release, joins CrossOver and Sikarugir on the same [Wine layer](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/runtimes/WINE.md). Settings, translators, private environments, graphics effects and the Steam client bridge work alike in all three. MacLauncher downloads WineCX releases after consent, and each launch checks the files that installation recorded, so **Runtimes → WineCX** offers no **Register custom…**. **Refresh** reads the newest release's macOS requirement from the start of its archive, and a version that needs a newer macOS is listed with **Requires macOS 26 or later** and is not downloaded. WineCX includes no D3DMetal; a D3DMetal version from **Runtimes** can be selected for its games.
- When D3DMetal handles a game's DLSS through game temporal integration, in a Wine that reads D3DMetal's adapter variables such as the one in WineCX, the game sees an NVIDIA GeForce RTX 4090 and offers its DLSS option. Setting `D3DM_VENDOR_ID`, `D3DM_DEVICE_ID` and `D3DM_DEVICE_DESCRIPTION` in the [environment variables](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/runtimes/TRANSLATOR_ENVIRONMENT.md#d3dmetal) replaces these values. Wine versions installed by earlier versions of MacLauncher are read again without a download, so they gain this and the other capabilities their Wine supports.
- Sikarugir and WineCX games start from a private application bundle in the games category, so macOS turns on Game Mode for them in full screen. On macOS 15 and later, macOS asks once per runtime, with a message that names Sikarugir or WineCX, whether its games may use the local network. The answer covers every game and version of that runtime, Play does not wait for it, and the game's **Network access** setting still applies. [Wine runtimes](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/runtimes/WINE.md#shared-behavior) describes the bundle.
- A Vulkan driver selected for a game, such as MacLauncher KosmicKrisp, loads in place of the Wine build's own MoltenVK with every Direct3D engine. Before, a WineCX game, or a CrossOver game on DXMT or D3DMetal, kept the Wine build's MoltenVK.
- A translator set that ships its own DXGI for only one game architecture, such as WineCX 4.8.1's DXVK, is offered only to games of that architecture. WineCX's DXMT uses the Wine engine's `winemetal.so`, so Direct3D 11 games start on it. The macOS requirements of DXMT and D3DMetal come from their installed libraries on every Wine source.
- **Runtimes** and the inspector name CrossOver, Sikarugir and WineCX alike, with version labels such as **Sikarugir 1.0.24 · Wine 10.0 rev 8** and **WineCX 4.8.1 · Wine 11.19**, and an installed version's **Includes** line lists its translators in one order.
- A saved **Runtimes** default that is not installed gives way to a compatible installed version, such as an installed Sikarugir or WineCX version, so Play asks for no download. **Install** in Runtimes installs the saved default itself, and a version chosen for one game stays exact. [Runtimes](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/runtimes/README.md#versions) describes the selection.
- Windows .NET and XNA games reach Wine Mono through a short Windows drive path, so a long launcher data path no longer stops Mono from finding its files.
- The [Steam client bridge](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/runtimes/WINDOWS_STEAM.md) also applies to a portable Windows game identified by a `steam_appid.txt` in its own folder that holds one valid app ID.
- New game types play Doom-engine games on [UZDoom](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/game-types/DOOM_ENGINE.md), Build-engine games on [Raze](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/game-types/BUILD_ENGINE.md), and the LucasArts titles that no other game type covers, such as Star Wars: Dark Forces and Outlaws, on [DREAMM](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/game-types/DREAMM.md). Each engine is its publisher's macOS app, downloaded after consent. The game data stays in place, each engine's configuration, saves and logs stay with the game in MacLauncher's data, and **Stop** asks the engine to quit. A [DOS game](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/game-types/DOS.md#uzdoom-raze-and-dreamm) whose folder holds exactly one main game file of one of these engines offers that engine as a runtime, including DOS games imported earlier.
- A converted [AnyPS5](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/game-types/PS5.md#anyps5) game runs from its own prepared macOS application, with the game's library title as its application name and its artwork as its Dock icon. Existing conversions move into this layout without converting again.
- An exported [Godot](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/game-types/GODOT.md#standard-and-net-variants) 3 game without C# always runs on the Standard build. Godot 3's .NET build stops at startup on such a game, which Play had used when only the .NET build of the game's version was installed. In the inspector, **.NET** is disabled for these games, with the reason under the **Variant** menu.
- [KiriKiri](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/game-types/KIRIKIRI.md#kirikiri-sdl2) games that use KAG3 start with KiriKiri SDL2 MCLv9 from MacLauncher Builds, whose package carries the KAG3 scripts and font. With MCLv7 they stop because its KAG3 resource manifest has an incompatible format. **Reload versions** and **Install** in **Runtimes → KiriKiri** add MCLv9, in this and earlier versions of MacLauncher.
- Hosted web games, such as RPG Maker MV and MZ, run without an HTTP disk cache, which only held a second copy of the game's files. The cache folder that earlier versions left for a game is removed when the game next starts; saves and storage stay.
- [Frame generation](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/graphics/FRAME_API.md) shows every generated frame the display can take. With 4× generation from 15 processed frames per second, 60 frames per second reach the screen on 60 Hz, 120 Hz and faster displays. For this, the Metal display link runs at the display's full refresh rate, and a frame that is due waits for a drawable instead of being discarded. Delivered frames are also presented on a command queue used only for display, so generated frames do not wait behind the game's own GPU work.
- Turning frame generation off, or removing its row, keeps the game image updating. The presenter releases its display link while frame generation is off and creates a new one when frame generation turns back on. LSFG frame generation keeps running after a graphics edit, such as a multiplier change or toggling another row.
- New DLSS rows and the DLSS preset start from a 540-pixel input, the size at which DLSS keeps pace for 4× frame generation to reach 60 frames per second on an M2 MacBook. The preset is now named **DLSS · 540p + LSFG 4×**.
- On a game that upscales with FidelityFX on Vulkan or Direct3D 12, the [FidelityFX API adapter](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/runtimes/CROSSOVER.md#fidelityfx-api-adapter) passes the game's depth, motion vectors, jitter, exposure and camera to the selected temporal upscaler, so upscalers such as MetalFX are no longer listed under **Needs scene inputs**. Turning **Graphics** off while the game runs hands its upscaling back to the game's own FidelityFX within about a tenth of a second, and turning it on brings the selected upscaler back from the next frame.
- When a game frame arrives while the game's earlier frames still hold the graphics processing images, processing adds another image, up to eight of each size and format, so that all frames in flight fit after a few refused frames. Before, a game whose earlier frames were still on the GPU could have about half of its scene frames refused for the whole session. [Status and delivery](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/graphics/STATUS_AND_DELIVERY.md) describes the capacity.
- Games on DXMT with MacLauncher's [camera adapter](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/runtimes/CROSSOVER.md#temporal-upscaling), which hands Streamline camera data to FSR 2 and FSR 3, no longer crash at startup when they clear unordered access views while initializing.
- The inspector counts an effect row as running when any of the game's graphics contexts runs it, so a temporal upscaler that runs in the game's renderer no longer reports **Some effects are not running**. Status details name rows as the graphics editor does.
- **Save processed screenshot** also saves the game's own frame while processing is off or no effect is selected, in Metal and OpenGL games.
- A shader row's options end with **Import options…**, **Copy options** and **Paste options**. Import takes the matching values from a RetroArch `.slangp` or ReShade `.ini` preset, and Copy and Paste move a row's values as preset text between rows and presets. [Shader options](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/graphics/EFFECT_PLANS.md#shader-options) describes the parsing and matching, including ReShade's compiled option names.
- The inspector's **Version** menu starts with **Automatic (vX)**, where vX is the version Play uses when the game has no version choice: a compatible installed version, otherwise the version Play installs. The lookup runs offline, and the entry reads **Automatic** until it answers. A saved choice that Play meets with an installed build, such as Godot 3.5.2 met by 3.5.2-stable, shows as that build.
- Default game icons appear in the library of the packaged app, where 0.6.0 left empty tiles. Game records store a default icon as a reference to its game type, so the icon follows the app when it moves or updates. The library's first paint shows every unchanged game icon, and local artwork in the Steam and External lists appears with its row. Games found unavailable at the last check, such as games on a disconnected drive, show as unavailable from the first paint.
- **Play** shows the game as starting at once, even while a sleeping drive answers the game's file check, and **Cancel** stops it during that check. Under heavy load, Play no longer stops with **The game's location is not responding.**, because the location's three-second limit starts when the check begins reading it.
- A runtime choice shows at once while the game's save locations refresh afterwards; when they cannot be read, a note under Play names the runtime. The cheat overlay's **Tools** button choice also shows at once and returns to the last applied choice when patching the game fails.
- **Settings**, **Runtimes** and **Credits** open without a loading pause, from one window that is prepared in the background. Views opened in quick succession each get their own window, which appears at once and fills in its controls and data as they load. The [UI guide](https://github.com/procrastinine/maclauncher/blob/v0.7.0/docs/development/UI_GUIDE.md#layout-overview) describes the windows.
- At startup, MacLauncher prepares the modules of the most recently played games first, and a game selected meanwhile waits at most for the module being prepared. Installed Wine versions, ScummVM's signature check and the graphics catalog are read without holding up the inspector.
- Buttons for settings, folders, removal and closing are now icons. The runtime settings gear sits beside the **Runtime** menu and brings a game's open runtime settings window forward instead of opening another. The game list meets the inspector without a gap, the inspector header has its own separator, and in the stacked layout the scrollbars sit in the window's right margin. Inspector statuses take one line, with their explanation in help.
- **Settings**, **Runtimes**, **External** and **Credits** no longer repeat the window title as a heading. **External** opens on its tabs, with the Steam account controls at the top of the **Steam** tab and **Open downloads in Finder** in the **Downloaded** toolbar, and its Epic, GOG and itch.io tabs open their sign-in introduction with the store's logo. Links in **Credits** open directly, and Settings buttons and shortcut names use sentence case. Progress bars without a known amount sweep with a continuous animation, which slows with Reduce Motion.
- Files dragged onto the window from outside MacLauncher cover the whole window with the drop target and close any open menu. Drags that start inside MacLauncher no longer open it.
- With `--wait`, the command line returns a game's exit status after the game's captured output has closed.
