# Neural rendering provider

`MacLauncherNeural` is the provider behind MacLauncher's neural rendering. It adapts the [MLX-DLSS Swift libraries](https://github.com/iamwavecut/MLX-DLSS/tree/7870371e8bf6c03967213f1a5d40db6c5a3bee38) to the graphics pipeline's IOSurface frames, using the source at commit `7870371e8bf6c03967213f1a5d40db6c5a3bee38` with MLX Swift `0.31.6`. The provider requires Apple Silicon and macOS 14 or later, and its offline video executable requires macOS 26 or later.

Each provider serves one game and owns a sequential renderer and its temporal history. Frames reach it through a C interface, which accepts matching BGRA8 IOSurface-backed `CVPixelBuffer`s in top-left row order and an `MTLSharedEvent`. Because the interface expects top-left rows, the native shader adapter normalizes a declared bottom-left origin before submission and restores that origin, with the original alpha, on output.

The shared event synchronizes the two sides. The caller initializes the source and destination, signals the producer value and waits for the completion value in its existing command buffer. Meanwhile, the provider waits asynchronously, converts the input on the GPU, renders, copies the result into the destination and restores the source alpha bytes before signaling completion. It never commits or waits for the caller's command buffer. One active and one pending frame are accepted.

Different providers may render concurrently, including a retiring provider and its replacement. Upstream's immutable kernel-parameter cache, however, is shared by the whole process, so MacLauncher's build adaptation synchronizes its lookup and rechecked insertion. Allocation and evaluation remain outside the cache lock, because MLX compilation can enter the model while holding its own evaluation lock. Concurrent misses may therefore allocate duplicate constants, but only one evaluated immutable value is published and returned for each key. Each provider's model and history remain isolated, as before.

The intensity control defaults to 1 and is passed directly to upstream neural rendering. At zero intensity, the provider copies the source without loading weights. Neural rendering operates on opaque SDR frames, so a GPU alpha check copies nonopaque frames unchanged before a model is loaded, and only the check's scalar result crosses to the CPU.

Frames are rendered independently by default. When temporal rendering is enabled, it uses bidirectional optical flow from VideoToolbox or Vision. Optical flow and model history follow the consecutive rendered images, so skipped producer frame IDs do not clear history, while explicit resets, source rewinds, extent changes, failures and detected scene changes start new history. Independent frames require no motion estimate. Both modes use processing scale 1. Network extents are padded to multiples of 64, with a minimum of 320 pixels per axis, and then cropped to the original frame extent, so a logical 854×480 frame runs at 896×512.

Independent rendering can reuse the result for a frame that has not changed. For this, it keeps one exact source snapshot and its rendered result, with a combined limit of 64 MiB per provider. The GPU alpha check also compares source bytes, and an unchanged opaque frame reuses that result, including when the producer skipped frame IDs between accepted images. The completion of such a frame carries the message `Exact-frame cache`, which distinguishes output reuse from a new inference, whereas a changed frame runs the complete FP16 Metal model. Resets, repeated or backwards frame IDs, size changes and errors discard the reusable result. Temporal rendering does not reuse independent results, and frames that exceed the cache limit run normally without keeping a snapshot.

When rendering fails, the original frame is copied on the provider's command queue. A frame that is never produced is released after 10 seconds or when the provider is destroyed, without reading its storage, and the caller's initialized destination remains the fallback. GPU publication errors report failure and restore source rows from shared storage before releasing the event. Completion messages are valid only during the completion callback.

Video files are processed by a separate executable, `maclauncher-neural-video`, which wraps upstream `NativeMediaProcessor.processVideo`. It takes an input, a new output path and a local `.dlssmodel` package, and its optional controls include temporal rendering, intensity, codec, processing scale, detail and colour strength. It reports its state as JSON lines with `progress`, `complete`, `cancelled` or `error` types. SIGINT and SIGTERM cancel the task on the main executor, and cancellation waits for the writer's cleanup, removes intermediate files and exits with code 130. Existing output files are preserved.

The Swift package produces `libMacLauncherNeural.dylib` and `maclauncher-neural-video`, and the MLX Metal library must be available beside them as `mlx.metallib` or through its matching SwiftPM resource bundle. To build them, `build.sh` takes the existing local source checkout that `MACLAUNCHER_MLX_DLSS_SOURCE` selects and prepares the synchronized source, with the cache synchronization applied, before invoking SwiftPM. Direct SwiftPM commands require that prepared source path as well, so a build cannot silently omit the adaptation. At run time, the provider downloads nothing. Models are supplied separately as a directory containing `manifest.json` and `weights.safetensors`, and upstream validates the manifest, the weights' SHA-256 that it records, and the tensor names, types and shapes before inference.

The provider is compiled by [MacLauncher Builds](https://github.com/procrastinine/maclauncher-builds/tree/main/producers/maclauncher/src/modules/shared/reshade/neural) from the selected source checkout and Swift package dependencies, and the original checkout stays unchanged. The resulting `provider.json` records the ABI, source commit, architecture, macOS floor, file sizes and SHA-256 values. Before starting the video executable, the app's `offline.js` checks the installed files against the file list in this record and validates the model package.

MLX-DLSS source is Apache-2.0 and MLX Swift is MIT. Extracted NVIDIA model weights retain their vendor terms and are not included or redistributed. The upstream [publication terms](https://github.com/iamwavecut/MLX-DLSS/blob/7870371e8bf6c03967213f1a5d40db6c5a3bee38/PUBLICATION.md) describe the separate restrictions on recovered model tooling and data.
