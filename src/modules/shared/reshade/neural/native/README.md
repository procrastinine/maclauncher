# Neural rendering provider

`MacLauncherNeural` adapts the [MLX-DLSS Swift libraries](https://github.com/iamwavecut/MLX-DLSS/tree/7870371e8bf6c03967213f1a5d40db6c5a3bee38) to the graphics pipeline's IOSurface frames. The source pin is `7870371e8bf6c03967213f1a5d40db6c5a3bee38`, with MLX Swift `0.31.6`. The provider requires Apple Silicon and macOS 14 or later. The offline video executable requires macOS 26 or later.

Each provider owns a sequential renderer and temporal history for one game. The C interface accepts matching BGRA8 IOSurface-backed `CVPixelBuffer`s in top-left row order and an `MTLSharedEvent`. The native shader adapter normalizes a declared bottom-left origin before submission and restores that origin with the original alpha on output. The caller initializes the source and destination, signals the producer value, and waits for the completion value in its existing command buffer. The provider waits asynchronously, converts the input on the GPU, renders, copies the result into the destination and restores the source alpha bytes before signaling completion. It never commits or waits for the caller's command buffer. One active and one pending frame are accepted.

Different providers may render concurrently, including a retiring provider and its replacement. The owned build adaptation synchronizes upstream's process-wide immutable kernel-parameter cache lookup and rechecked insertion. Allocation and evaluation remain outside the cache lock because MLX compilation can enter the model while holding its own evaluation lock. Concurrent misses may allocate duplicate constants; only one evaluated immutable value is published and returned for each key. Per-provider model and history isolation remain unchanged.

Intensity defaults to 1. The provider passes this control directly to upstream neural rendering. Zero intensity copies the source without loading weights. Neural rendering operates on opaque SDR frames. A GPU alpha check copies nonopaque frames unchanged before loading a model, with only its scalar result crossing to the CPU. Temporal rendering is disabled by default; enabling it uses bidirectional optical flow from VideoToolbox or Vision. Optical flow and model history follow the consecutive rendered images, so skipped producer frame IDs do not clear history. Explicit resets, source rewinds, extent changes, failures and detected scene changes start new history. Independent frames require no motion estimate. Both modes use processing scale 1. Network extents are padded to multiples of 64 with a minimum of 320 pixels per axis, then cropped to the original frame extent. A logical 854×480 frame therefore runs at 896×512.

Independent rendering retains one exact source snapshot and its rendered result, with a combined limit of 64 MiB per provider. The GPU alpha check also compares source bytes; an unchanged opaque frame reuses that result, including when the producer skipped frame IDs between accepted images. Its rendered completion carries the message `Exact-frame cache`, distinguishing output reuse from a new inference. Changed frames run the complete FP16 Metal model. Resets, repeated or backwards frame IDs, size changes and errors discard the reusable result. Temporal rendering does not reuse independent results. Frames exceeding the cache limit run normally without retaining a snapshot.

Rendering errors copy the original frame on the provider's command queue. An unproduced frame is released after 10 seconds or provider destruction, without reading its storage; the caller's initialized destination remains the fallback. GPU publication errors report failure and restore source rows from shared storage before releasing the event. Completion messages are valid only during the completion callback.

`maclauncher-neural-video` wraps upstream `NativeMediaProcessor.processVideo`. It accepts an input, a new output path and a local `.dlssmodel` package. Optional controls include temporal rendering, intensity, codec, processing scale, detail and colour strength. It emits JSON lines with `progress`, `complete`, `cancelled` or `error` types. SIGINT and SIGTERM cancel the task on the main executor. Cancellation waits for writer cleanup, removes staging files and exits with code 130. Existing output files are preserved.

The Swift package produces `libMacLauncherNeural.dylib` and `maclauncher-neural-video`. The MLX Metal library must be available beside those artifacts as `mlx.metallib`, or through its matching SwiftPM resource bundle. `MACLAUNCHER_MLX_DLSS_SOURCE` selects an existing local source checkout for `build.sh`; the script prepares the synchronized source before invoking SwiftPM. Direct SwiftPM commands require that prepared source path, so a build cannot silently omit the adaptation. The runtime performs no network acquisition. Models are supplied separately as a directory containing `manifest.json` and `weights.safetensors`; upstream validates the manifest, digest, tensor names, types and shapes before inference.

The parent `build.mjs` uses the registered, pinned `src/external/MLX-DLSS` source and uses configurable compiler workspaces. `native/prepare-upstream.mjs` copies tracked inputs into an owned tree, verifies the exact adapted source digest and applies the kernel-parameter cache synchronization without modifying the checkout. `adaptation.json` records the upstream and applied file digests. It obtains the matching Metal library from the official MLX Swift 0.31.6 release artifact, verifies both checksums in `upstream.json`, and includes source notices with the two binaries. Compiler prefix maps remove local source paths. The resulting `provider.json` records the ABI, source commit, architecture, macOS floor, file sizes and SHA-256 values. The parent `offline.js` validates that installed inventory and model package before spawning the video executable.

MLX-DLSS source is Apache-2.0 and MLX Swift is MIT. Extracted NVIDIA model weights retain their vendor terms and are not included or redistributed. The upstream [publication terms](https://github.com/iamwavecut/MLX-DLSS/blob/7870371e8bf6c03967213f1a5d40db6c5a3bee38/PUBLICATION.md) describe the separate restrictions on recovered model tooling and data.
