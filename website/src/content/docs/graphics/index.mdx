Every game you play through MacLauncher passes through the same graphics layer on its way to your Mac's screen. The layer is built on [Metal](https://developer.apple.com/metal/), Apple's interface for drawing with the GPU. It receives each finished image from the [runtime](/maclauncher/background/choosing-a-runtime/) that drew it (the engine, player or emulator running the game) and lets you process that image before it reaches the window. You can upscale it, sharpen it, clean it up with a neural network or give it the look of a CRT screen. You can also insert generated frames between the real ones, or combine several of these steps.

Because the layer sits between the runtime and the window, it serves almost everything MacLauncher runs: native Mac apps, [Godot](https://github.com/godotengine/godot) and [RPG Maker](https://www.rpgmakerweb.com/) games, visual novels, Android and iOS games, browser games, videos, and Windows games running in [CrossOver](https://www.codeweavers.com/crossover/), CodeWeavers' paid app for running Windows software on the Mac. Anything MacLauncher can launch can have effects applied to it. On macOS 15.2 or later, so can [the window of any other app, or a whole display](/maclauncher/graphics/window-graphics/).

The graphics layer works on Intel and Apple Silicon Macs, although some effects ask for more. Models that run on [MLX](https://github.com/ml-explore/mlx), Apple's machine-learning framework, and features from Metal 4 need Apple Silicon and a newer macOS. Shaders written for [libplacebo](https://libplacebo.org/) (the rendering library behind the mpv video player) or in the ISF format follow the requirements of the graphics package included with MacLauncher. Support for [MetalFX](https://developer.apple.com/documentation/metalfx), Apple's own upscaler and frame interpolator, depends on your GPU, and MacLauncher checks the GPU directly. When your Mac can't run an effect, that effect is switched off and the others keep working. [Macs and macOS versions](/maclauncher/macs-and-macos/#graphics-features-by-macos-version) lists which features need which macOS version, and the [requirements reference](https://github.com/procrastinine/maclauncher/blob/master/docs/runtimes/SYSTEM_REQUIREMENTS.md#graphics) has the complete tables.

## The chain

Effects live in an ordered list called the chain, which holds up to 32 rows. The image enters at the top, and each row does one thing to it before handing it to the next. Whatever leaves the last row is fitted to the window. A chain can be a single sharpening pass, or something longer like this:

1. Downsample the game's image to 540p, so the expensive steps have fewer pixels to process.
2. Run a neural model on that smaller image.
3. Upscale the result to the window with MetalFX.
4. Add frame generation to raise the frame rate shown on screen.
5. Apply a CRT shader to the final image.

You choose the order, and it changes the result: a CRT effect looks different before an upscaler than after one, and so does sharpening placed before or after a neural model. [Building a chain](/maclauncher/graphics/composing-effects/) explains how rows interact.

## Simple and Advanced

Each game's inspector has a **Graphics** section that shows the chain in two views. **Simple** is the quick one, with a dropdown for each group of methods: **Image filters**, **Resize** (Downsample and Upscale) and **Temporal** (temporal upscaling and frame generation). Once you pick a method in a group, Simple works out the sizes the image is processed at.

**Advanced** shows every row in order. Its **Add effect…** button adds an image filter, a downsample, an upscale, a temporal upscaler or a frame generator, and each row can then be dragged to a new position, resized, adjusted or switched off. Because both views edit the same chain, you lose nothing by switching between them.

To try both views, open the [interactive demo](/maclauncher/demo/), select a game and scroll its inspector to **Graphics**. Picking an effect there brings up the article about it.

## The Graphics heading

Clicking the **Graphics** heading opens and closes the section, and while it's closed the heading summarizes the active effects. Its checkbox turns the whole chain off and on without changing any of it, which is handy for setting a chain aside and bringing it back later.

To reuse a chain on other games, save it as a preset. The **⋯** menu beside the heading applies a saved preset, saves the current chain with **Save as preset…**, opens **Manage presets…** and empties the chain with **Clear effects**. If you apply a preset or clear the chain by mistake, **Undo** brings back the previous chain until your next edit.

## Changes apply live

Edits apply while the game runs, in a window or fullscreen, as long as MacLauncher's connection to that game's graphics supports live changes. When it doesn't, the inspector says the change takes effect at the next launch. Shaders compile and models load in the background, so the game keeps drawing in the meantime. A few settings depend on something the game's renderer sets up at startup, and their controls point that out.

To see what an effect changes, **Output → Compare** shows the untouched source, a split view, or the difference between the source and the processed image. To see what it costs, **Output → Performance overlay** draws frame rates, GPU time and latency over the game. [Performance and presentation](/maclauncher/graphics/composing-effects/#performance-and-presentation) describes the overlay together with the frame-rate cap and display settings.

## Two kinds of input

Most effects need only the finished picture. Color filters, CRT shaders, some frame generators, and upscalers that look at one frame at a time (spatial and neural upscalers) work on any game, because every game produces a picture.

Other effects need more. Temporal upscalers, which build a sharper image out of several frames in a row, are one group: MetalFX Temporal, AMD's [FSR](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK) 2 to 4 and Intel's [XeSS](https://github.com/intel/xess). Scene-based frame generators and depth effects such as ambient occlusion and depth of field are another. All of these also use data from the game's renderer: its depth buffer (how far away each pixel is), its motion vectors (how each pixel moved since the previous frame) or its camera data. Only some runtimes pass that data to MacLauncher, so these effects work in some games and not in others. When a game doesn't supply what an effect needs, the menus list the effect under **Needs scene inputs**.
