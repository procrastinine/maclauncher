Games often draw fewer pixels than your Mac's display has, and upscaling enlarges their image to fill it. A pixel-art game might render at 320×180, an older 3D game at 720p, and a demanding one at whatever resolution keeps it running smoothly. On a Retina screen, the method chosen for that enlargement changes the result considerably.

In MacLauncher, the enlarging is done by an **Upscale** row in the effect chain. By default it fills the window or the fullscreen surface; it can also use a fixed size or a multiple of its input. The samples below enlarge two very different images 4× with each method, cropped so individual pixels are visible: a frame of [Celeste](https://store.steampowered.com/app/504230/Celeste/), which draws its pixel art at 320×180, and a frame of Ciri from [The Witcher 3: Wild Hunt](https://store.steampowered.com/app/292030/The_Witcher_3_Wild_Hunt/), reduced to 480×270. Choose a game, then a method; the method stays selected when you switch games.

## Spatial upscalers

Spatial upscalers use a single finished image, so they work with every game.

- <span id="classic-filters"></span>**Nearest**, **Bilinear** and **Bicubic** are the classic filters. Nearest copies pixels, bilinear blends neighboring pixels, and bicubic blends a wider neighborhood for a little more sharpness.
- <span id="libplacebo-filters"></span>**[libplacebo](https://libplacebo.org/) filters** add the kernels used by video players, such as Lanczos, EWA Lanczos, Spline36, Mitchell and Catmull-Rom. Their macOS requirement comes from the graphics package included with MacLauncher, and the [requirements reference](https://github.com/procrastinine/maclauncher/blob/master/docs/runtimes/SYSTEM_REQUIREMENTS.md#graphics) lists it.
- <span id="metalfx-spatial"></span>**[MetalFX Spatial](https://developer.apple.com/documentation/metalfx)** is Apple's upscaler, built into macOS 13 and later and available on Macs whose GPU supports it.
- <span id="fsr-1"></span>**[AMD FSR 1](https://github.com/GPUOpen-Effects/FidelityFX-FSR)** is AMD's edge-adaptive upscaler with its RCAS sharpening pass, ported to [Metal](https://developer.apple.com/metal/). Its **Sharpness** control runs from 0 to 1.
- <span id="mako"></span>**[MAKO](https://github.com/eugeniosegala/MAKO)** spatial scaling is another reconstruction filter, with sharpening built in.
- <span id="lossless-scaling-ls1"></span>**[Lossless Scaling](https://store.steampowered.com/app/993090/Lossless_Scaling/) LS1** is the upscaler from Lossless Scaling. It uses the model files from your own purchased copy, which **Runtimes → Effects → Upscaling** can import or download through [Steam](https://store.steampowered.com/). [Getting Lossless Scaling files](/maclauncher/graphics/frame-generation/#getting-lossless-scaling-files) describes the options.

## Shader upscalers

Shader collections add many upscalers written for video players and emulators, and most of them are tuned for one kind of image:

- [Anime4K](https://github.com/bloc97/Anime4K), [ArtCNN](https://github.com/Artoriuz/ArtCNN), [CuNNy](https://github.com/funnyplanter/CuNNy) and [ACNet/ARNet](https://github.com/TianZerL/ACNetGLSL) are made for anime and line art. They are small neural networks that run as ordinary GPU shaders, and they often suit visual novels well.
- [FSRCNNX](https://github.com/iwalton3/default-shader-pack), [RAVU and NNEDI3](https://github.com/bjin/mpv-prescalers) are made for general video, as is the included SSimSuperRes pass, which refines an upscaled image against its lower-resolution source.
- [xBRZ](https://github.com/libretro/slang-shaders/tree/master/edge-smoothing/xbrz), [SABR](https://github.com/libretro/slang-shaders/tree/master/edge-smoothing/sabr) and the other pixel-art scalers in the [libretro Slang collection](https://github.com/libretro/slang-shaders) smooth diagonal edges while keeping the hand-drawn look of pixel art.

A shader that always doubles its input appears as an Upscale with its 2× scale, and a later resize row can fit the result to the window. [Shader collections and imports](/maclauncher/graphics/shaders/) covers installing collections, and [Neural upscaling and restoration](/maclauncher/graphics/neural-restoration/) covers the heavier model-based upscalers.

## Temporal upscalers

A spatial upscaler has one image to work from, while a temporal upscaler gathers detail across several frames. The game renders each frame with a tiny sub-pixel offset called jitter, and the upscaler uses the game's depth buffer and motion vectors to line those frames up and rebuild a sharper picture. Modern games use this technique to render a fraction of the pixels and still look sharp.

MacLauncher includes these temporal upscalers:

- <span id="metalfx-temporal"></span>**[MetalFX Temporal](https://developer.apple.com/documentation/metalfx)**, plus its [denoised variant](https://developer.apple.com/documentation/metalfx/mtlfxtemporaldenoisedscaler) on macOS 26 or later
- <span id="fsr-temporal"></span>**AMD [FSR 2.2](https://github.com/GPUOpen-Effects/FidelityFX-FSR2)**, **[FSR 3.1](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK)** and **[FSR 4.1](https://github.com/UzenUPoZiTiV4ik/fsr4-native-macos)**; FSR 4.1 has Exact Fast, Lite and Lite 2 profiles and needs Apple Silicon with macOS 15 or later
- <span id="arm-asr-and-snapdragon-gsr-2"></span>**[Arm ASR](https://github.com/arm/accuracy-super-resolution-generic-library)** and **[Snapdragon GSR 2](https://github.com/SnapdragonGameStudios/snapdragon-gsr)**
- <span id="xess"></span>**[Intel XeSS](https://github.com/intel/xess)**, which runs Intel's own Windows library through D3DMetal or KosmicKrisp on Apple Silicon
- <span id="dlss-sr"></span>**DLSS SR** for scenes, through [MLX-DLSS](https://github.com/iamwavecut/MLX-DLSS)

All of them need depth, motion and camera data from the game itself, which a finished picture cannot supply. They run only in games whose runtime passes that data to MacLauncher; for other games, the spatial and neural upscalers are the options.

## Render size versus window size

Upscaling pairs well with rendering fewer pixels in the first place, and MacLauncher has two separate controls that reduce the size.

<span id="game-resolution"></span>**Game resolution** asks the game itself to render at a smaller size, which saves the game real work. When the game's renderer can't change its size, MacLauncher uses a virtual window if one is available: the game is shown in a separate, resizable output window, while it keeps drawing into its original window, which can then be made smaller. Otherwise, MacLauncher shrinks the finished image before the effects run. That fallback saves work in the effects but not in the game's own rendering.

<span id="downsample"></span>A **Downsample** row shrinks an image that has already been rendered. The game doesn't get faster, but every effect after the row has fewer pixels to process, which matters most for neural models.

In both cases the window keeps its size, and only the processing resolution changes. [Building a chain](/maclauncher/graphics/composing-effects/) has more on sizes. The graphics guide's [size section](https://github.com/procrastinine/maclauncher/blob/master/docs/graphics/README.md#rendering-processing-and-output-size) describes every size option, and the algorithm reference lists the requirements of each [spatial](https://github.com/procrastinine/maclauncher/blob/master/docs/graphics/PROVIDERS.md#spatial-resizing) and [temporal](https://github.com/procrastinine/maclauncher/blob/master/docs/graphics/PROVIDERS.md#scene-temporal-upscaling) upscaler.
