In MacLauncher, the graphics effects for a game on macOS are combined in an effect chain, a list of up to 32 rows in which effects can go in any order and any combination. This page explains how rows interact and how sizes work, and gives a few example chains to start from.

## Top to bottom

The image enters at the top of the chain and passes through each enabled row in turn. Each row receives the output of the row above it, so the order changes the result:

- Sharpening before an upscaler sharpens the small image, and the upscaler then enlarges the sharpened edges; sharpening after the upscaler works on the final pixels. Both are valid choices with different results.
- A CRT effect belongs after the image has been enlarged, so it has enough screen pixels to draw scanlines with.
- Color grading before a CRT grades the game, while a grade after the CRT also tints the simulated glass and glow.
- An expensive model costs least early in the chain, at a small size, before anything enlarges the image.

Rows come in five kinds. **Image filters** keep the size, **Downsample** and **Upscale** change it, and **Temporal upscaling** and **Frame generation** work across frames. When you add a shader, MacLauncher places it by the output size it declares, so a shader that always doubles its input appears as an Upscale.

## Editing rows

Rows are edited in the **Advanced** view, which shows the full chain in order. There, **Add effect…** adds a row of any kind, and dropping a shader file on a row replaces that row's effect. You can drag a row or move it with Option-Up and Option-Down, switch it off to set it aside with its settings intact, or remove it. Each row also has **Options**, which holds its parameters and size, and **Details**, which shows what the row is doing while the game runs. A row that can't run as saved, for instance because its shader file is missing, stays off and shows **Needs attention** with the reason, and the rest of the chain keeps running.

## Sizes

Downsample and Upscale rows can each set their size in three ways:

- a scale of the previous image, such as 0.5× or 2×
- a fraction of the window or fullscreen surface, such as 100%
- a fixed resolution, such as 540p or 1920×1080

By default, a Downsample halves its input and an Upscale fills the window. Models and shaders with a fixed scale keep it (a 4× model always outputs 4×), and a later Upscale or Downsample row can then fit their result to the window. To check what a row actually receives and produces, its **Options** and **Details** show the input and output size it sees. Whatever happens inside the chain, the window keeps the size you gave it, and the last image is fitted to it.

<span id="adaptive-quality"></span>A **Downsample** row can also use **Adaptive quality**, which adjusts its working size within bounds you set to stay inside a GPU time budget.

## Recipes

### Pixel art with a CRT

<Steps>
1. **Upscale**: Nearest, to the window.
2. **CRT**: Simulated content height set to the game's original height.
3. **Colour**, for slightly stronger colors.
</Steps>

The [overview page](/maclauncher/graphics/) shows this chain on Sonic the Hedgehog 2, and [CRT and retro](/maclauncher/graphics/crt-and-retro/) compares other CRT shaders that can take the place of step 2.

### A sharper visual novel

<Steps>
1. **Upscale**: [Real-CUGAN](https://github.com/bilibili/ailab/tree/main/Real-CUGAN) 2×, or [Anime4K](https://github.com/bloc97/Anime4K), which costs far less.
2. **Upscale**: [MetalFX](https://developer.apple.com/documentation/metalfx) or Bilinear, to fit the result to the window.
3. **CAS Sharpen** at a low strength.
</Steps>

### DLSS neural rendering at a playable frame rate

[DLSS neural rendering](/maclauncher/graphics/neural-restoration/#dlss-neural-rendering) redraws every frame with a neural model. On a game like DOOM 3 the result can look close to a photograph, with weathered skin, woven cloth and softer, more natural light. The complete chain:

<Steps>
1. **Downsample** to 720p, so DLSS has far fewer pixels to redraw.
2. **DLSS neural rendering** on the 720p image.
3. **Upscale** with MetalFX Spatial to the window. See [Upscaling](/maclauncher/graphics/upscaling/).
4. **Frame generation** with [Lossless Scaling](https://store.steampowered.com/app/993090/Lossless_Scaling/) at 4×, which fills in the frames DLSS can't produce in time. See [Frame generation](/maclauncher/graphics/frame-generation/).
</Steps>

At 540p or 720p, the model redraws a fraction of the pixels, which makes DLSS fast enough to run in real time and keeps the game far more responsive than at full resolution. MetalFX then restores the sharpness, and frame generation smooths the motion. Input follows the frame rate after step 3, plus the small delay that generated frames add. A version of this chain is also available as the **DLSS · 540p + LSFG 4×** preset, which sets it up in one step.

### Frame generation alone

A single **Frame generation** row at 2× is often all a 30 fps game needs. As its generator, [**Automatic**](/maclauncher/graphics/frame-generation/#automatic) works without any downloads, while [RIFE](https://github.com/hzwer/Practical-RIFE) and Lossless Scaling use a downloaded model or your own Lossless Scaling files. See [Frame generation](/maclauncher/graphics/frame-generation/).

## Presets

Presets let you reuse a chain on other games. To make one, choose **Save as preset…** in the **⋯** menu beside the **Graphics** heading, which saves the current chain under a name, with every row, size and parameter. Applying a preset to another game copies it into that game, so later edits to the preset don't change games it was already applied to. A preset refers to the shaders and models it uses, which stay in the shared libraries. **Manage presets…** opens the saved presets in **Settings → Graphics → Presets**.

## Seeing what changed

To see what the chain changes, **Output → Compare** switches between the processed image, the untouched source, a split view with a movable divider, and the difference between the two. For a single row, **Details** shows its sizes and whether it's running, with a reason when it isn't.

## Performance and presentation

Besides **Compare**, the **Output** section has settings that leave the picture itself alone. Each one appears when the game's graphics support it, and changes to a supported setting apply while the game runs. A saved choice that cannot run stays visible as well, with the reason shown, and it applies once support is available.

- <span id="performance-overlay"></span>**Performance overlay** makes the cost of an effect, and whether frame generation keeps up, easy to see. It draws a small panel at the top left of the game with the captured, displayed and generated frame rates, GPU time, latency and how evenly frames are paced. The **Compact** layout shows three lines, while **Detailed** adds memory use, the parts that make up the latency, and running counts of captured, presented, generated, passed-through and dropped frames. The detailed layout also lists the GPU time of each row in your chain. Rows that the GPU processes in one batch share a measurement, and the overlay marks them.
- <span id="frame-rate-cap"></span>**Frame-rate cap** limits how often the game itself renders, from 10 to 1000 fps. A steady, lower frame rate can look smoother than one that swings up and down, and it also leaves GPU time for the effects. When graphics are applied to [another app's window](/maclauncher/graphics/window-graphics/), the cap limits how often MacLauncher takes frames from that window instead. Without a cap, MacLauncher never limits the game.
- <span id="display-sync-and-drawables"></span>**Display sync** and **Drawables** control how processed images reach the screen. Turning display sync off can lower latency in fullscreen, although it can cause tearing; in a window, macOS shows each image at the display's refresh either way. The **Drawables** setting decides how many output images can be in use at once, whether they are being drawn, waiting for the display or on screen. Two gives lower latency, while three keeps presentation smoother when GPU time varies.

## Shortcuts and screenshots

MacLauncher also has keyboard shortcuts for graphics, which are set in **Settings → Launcher**. The first two work from any app while a game runs:

- **Bypass graphics effects** turns the game's graphics off, or back on, just like its **Graphics** checkbox. Pressing it twice gives a quick before-and-after comparison.
- **Save processed screenshot** saves the game's image as you see it, with every effect applied, as a PNG file. The file is named after the game and the time, the way macOS names its own screenshots, and the performance overlay is left out. Screenshots go to a MacLauncher folder in your Pictures folder unless you pick another **Screenshot folder**, and they need the game's graphics to be on. An HDR game's screenshot stays HDR, as a 16-bit PNG.

With one game running, both shortcuts act on that game. With several, they act on the one in front, or on the most recently started one if none of them is in front.

The other two shortcuts are for [window graphics](/maclauncher/graphics/window-graphics/), which apply a chain to another app's window. **Toggle Graphics for Front App** works whether or not a game runs: it starts window graphics for the app in front, with a new row of its own, or takes them off again when that app already has them. **Toggle pointer in window graphics** hides or shows the pointer that MacLauncher draws on an enlarged window of the app in front.

To set a shortcut, click **Record Shortcut** and press the keys. A shortcut combines Control with at least two of Option, Shift and Command, such as ⌃⌥⌘B. Combinations like these are left free by macOS and most apps, and Settings turns down the few that macOS does use, such as ⌃⇧⌘3 for screenshots. Once active, a graphics shortcut takes precedence over the same keys in the app in front.

## Videos too

Videos opened in MacLauncher play through the same chain. **Export video…** can also render a video file with the saved chain applied, including neural models and image-pair frame generation. The sample images on this site were made that way.
